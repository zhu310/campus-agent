# 现场演示脚本

本文档用于 4-6 分钟现场演示。目标不是展示所有功能，而是稳定展示“高校事务办理闭环”。

## 1. 一句话定位

智审通 Campus Copilot 是面向高校行政与学生事务的一站式智能审核与材料办理 Agent 平台。它不是普通聊天机器人，而是把制度问答、材料解析、规则审核、表单预填、流程待办和记录留痕串成一个可复用的办理闭环。

## 2. 演示前准备

确认服务已经启动：

- 前端：`http://localhost:5173`
- 后端：`http://localhost:8000`
- 后端健康检查：`http://localhost:8000/health`
- Swagger 文档：`http://localhost:8000/docs`

确认演示材料：

- 比赛通知或制度文件
- 完整报名材料
- 缺失字段的报名材料
- 备用 TXT 文本

项目内置样例：

- `demo-assets/contest-notice.txt`
- `demo-assets/material-complete.txt`
- `demo-assets/material-incomplete.txt`
- `demo-assets/registration-template.txt`

## 3. 演示流程

### 步骤 1：打开 Dashboard

展示内容：

- 项目名称
- 已接入文档数量
- 审核记录
- 工作流记录

讲法：

> 这是面向高校事务办理的智能工作台，核心目标是减少人工核材料、查制度、填表和追踪流程的重复工作。

### 步骤 2：导入比赛通知或制度文件

操作：

1. 进入文件或知识库相关区域。
2. 上传比赛通知或使用内置比赛通知。
3. 将文档写入知识库。

讲法：

> 系统会解析通知内容，切分后写入向量库。后续问答只基于已导入材料检索，减少模型自由发挥。

### 步骤 3：进行 RAG 问答

推荐问题：

```text
单人能否参赛？
```

```text
报名截止时间是什么？
```

展示重点：

- 回答结论
- 引用依据
- 命中文档片段
- 建议动作

讲法：

> 这里不是让模型凭空回答，而是从制度或通知中检索证据，再生成可追溯回答。

### 步骤 4：上传报名材料

操作：

1. 上传完整材料或缺失材料。
2. 触发 OCR / 文档解析。
3. 展示识别出的文本和结构化字段。

展示重点：

- 项目名称
- 负责人
- 团队成员
- 学院或学校
- 电话
- 邮箱
- 指导教师

讲法：

> 系统可以处理 PDF、DOCX、图片等材料。OCR 不稳定时，DOCX 和备用文本可以作为现场降级方案。

### 步骤 5：运行材料审核

操作：

1. 点击审核材料。
2. 展示审核结论。

展示重点：

- 通过 / 待补充 / 退回
- 缺失字段
- 风险提示
- 规则依据
- 修改建议

讲法：

> 审核不是简单分类，而是把制度规则转为检查项，对材料完整性、人数要求、联系方式等进行结构化判断。

### 步骤 6：表单预填

操作：

1. 点击表单预填。
2. 展示自动生成的表单草稿。

展示重点：

- 字段映射
- 自动填入内容
- 需要人工确认的字段

讲法：

> 预填结果用于减少重复录入，后续可以扩展为 Word、PDF 或学校 OA 表单导出。

### 步骤 7：生成待办流程

操作：

1. 点击生成下一步。
2. 展示办理步骤。

展示重点：

- 下一步操作
- 截止时间
- 责任角色
- 风险提醒

讲法：

> 系统不只回答问题，还能给出后续办理计划，帮助学生或老师知道下一步该做什么。

### 步骤 8：查看记录留痕

操作：

1. 进入记录留痕页面。
2. 展示最近问答、审核、表单和流程记录。

讲法：

> 每次关键操作都会留下记录，方便后续追踪、复核和管理。

## 4. 收尾总结

推荐总结：

> 这个系统的价值不在于单点聊天，而在于把高校事务中最耗时的查制度、核材料、填表、生成待办和留痕管理串起来。同一套链路可以复用到比赛报名、请假、报销、奖助学金、社团活动审批等场景。

## 5. 现场备用方案

模型 API 失败：

- 使用 `DEMO_MODE=true`
- 展示已导入通知的检索与结构化审核能力

OCR 慢或识别差：

- 改用 DOCX
- 改用备用 TXT 文本

Qdrant 连接失败：

- 检查 `docker ps`
- 重启 `docker compose up -d`
- 使用内置示例继续演示审核、表单和流程链路
