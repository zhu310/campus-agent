# 思途杯方案

## 1. 比赛要求拆解

根据通知，Agent 赛道的要求是：

- Web 端展示，页面简洁、美观、大方，偏商务化
- 能解决真实应用场景问题
- 具备 `RAG 检索`、`工具调用`、`大模型调用`、`意图识别`
- 优先使用 `Python + React`
- 有创新思维、正能量、商业价值、社会价值
- 允许本地化部署国产模型，若有数据制作与微调可加分，但不是必须

时间节点：

- 报名截止：`2026-05-12 18:00`
- 培训时间：`2026-05-13` 至 `2026-05-16`
- 作品提交截止：`2026-05-30`
- 决赛路演：`2026-06-06`

奖项导向不是“技术炫技”本身，而是“最具商业价值金奖”。因此作品必须做到：

- 场景真实
- 闭环完整
- 可量化价值
- 演示稳定
- 界面专业

## 2. 建议作品方向

作品名建议：

`智审通 Campus Copilot`

一句话定位：

`面向高校行政与学生事务的一站式智能审批与材料办理 Agent 平台`

核心场景：

- 请假申请
- 报销申请
- 奖助学金材料核验
- 比赛报名材料审查
- 社团活动审批
- 校内通知问答与制度检索

优点：

- 完全贴合通知里的推荐项目“高校行政审批自动化 Agent”
- 场景人人能懂，老师一眼就知道价值
- 可以把 `RAG + OCR + 表单预填 + 规则审查 + 多 Agent 工作流` 串成完整闭环
- 天然兼具商业价值：学校、学院、企业行政、人事、园区服务都能复用

## 3. 产品目标

不要做“聊天机器人”，要做“会办事的智能体”。

目标闭环：

1. 用户上传通知、制度、申请材料、证明附件
2. 系统自动解析文档与图片
3. Agent 理解用户意图
4. RAG 检索相关制度和历史知识
5. 工具链执行材料核验、缺失项检查、表单预填、流程规划
6. 输出可执行结果和风险提示
7. 保存办理记录，支持后续追踪

评委现场看到的不是“能回答问题”，而是：

- 它知道该做什么
- 它能调用工具做事
- 它能给出依据
- 它能减少真实工作量

## 4. 功能设计

### 4.1 一级能力

- 智能问答：基于校内制度、通知、公文、比赛文件做可信问答
- 材料审核：识别上传材料中的姓名、学号、团队人数、附件类型、缺失字段
- 智能填表：根据上传内容自动生成结构化报名/审批表
- 流程规划：根据不同事务自动给出办理步骤、截止时间、所需材料、责任角色
- 审批建议：根据规则输出“通过 / 退回 / 待补充”
- 办理留痕：记录用户提问、上传材料、系统审查结果

### 4.2 二级亮点

- 多模态输入：文本、PDF、截图、照片、扫描件
- 证据引用：回答中明确展示命中文档片段
- 规则引擎：把“必须 3-5 人组队”“截止时间”等规则结构化
- 多 Agent 编排：问答 Agent、审核 Agent、填表 Agent、流程 Agent 协同
- 商业化驾驶舱：节省时间、减少遗漏、提高通过率的量化指标展示

### 4.3 决赛高光功能

- 一键生成“材料缺失清单”
- 一键生成“路演报名待办”
- 一键导出“审批结论摘要”
- 展示一份真实扫描材料，从 OCR 到审核结论全流程跑通

## 5. 技术路线

## 5.1 总体选型

- 前端：`React + TypeScript + Vite + Ant Design`
- 后端：`FastAPI`
- 工作流编排：`LangGraph`
- 关系数据库：`PostgreSQL`
- 向量数据库：`Qdrant`
- 文档解析：`pdfplumber + python-docx + unstructured`
- OCR：`PaddleOCR`
- 大模型：
  - 主模型：`Qwen / DeepSeek API`
  - 备选：`通义千问商业 API`
  - 本地加分版：`Qwen2.5-7B-Instruct` 或其他国产小模型
- Embedding：
  - 优先：`bge-m3` 或 `Qwen3-Embedding` 类中文效果较好的向量模型
- 重排：`bge-reranker`
- 图表展示：`ECharts`

## 5.2 数据库方案

- `PostgreSQL`
  - 存业务数据、用户会话、文档元数据、审核记录、规则配置、操作日志
- `Qdrant`
  - 存知识库 chunk、向量、payload 元数据、命中证据

推荐部署方式：

- 你的服务器 Docker 上长期部署 `postgresql + qdrant`
- 比赛现场本地电脑只跑 `frontend + backend`
- 若现场网络不稳，提前把一份精简数据和模型缓存打包到本机做降级演示

## 5.3 数据表设计

PostgreSQL 建议核心表：

- `users`
- `sessions`
- `documents`
- `document_chunks`
- `knowledge_bases`
- `audit_tasks`
- `audit_results`
- `form_templates`
- `form_fill_results`
- `workflow_runs`
- `tool_logs`
- `rule_policies`

Qdrant payload 建议包含：

- `document_id`
- `chunk_id`
- `title`
- `source_type`
- `department`
- `scenario`
- `updated_at`
- `keywords`
- `permission_level`

## 5.4 多 Agent 架构

推荐使用 `LangGraph` 做状态图，而不是简单 if/else。

Agent 划分：

- `Intent Agent`
  - 识别当前是问答、审核、填表、流程规划还是综合办理
- `RAG Agent`
  - 检索制度、通知、规则、案例
- `Audit Agent`
  - 对材料字段进行抽取和规则匹配
- `Form Agent`
  - 生成结构化表单
- `Workflow Agent`
  - 生成待办步骤和时间提醒
- `Supervisor Agent`
  - 汇总结果，给出最终用户答复

工具列表：

- `search_knowledge`
- `ocr_parse_file`
- `extract_fields`
- `validate_rules`
- `prefill_form`
- `generate_todo_plan`
- `save_record`


## 6. 页面与路演设计

前端不做成普通聊天页，做成 `三栏业务驾驶舱`：

- 左栏：知识库与上传区
- 中栏：智能办理工作台
- 右栏：证据引用、审核结论、表单结果、流程待办

首页突出三件事：

- 商业价值
- 办事闭环
- 数据化结果

展示指标卡：

- 已接入制度文档数
- 平均办理耗时下降比例
- 材料遗漏识别率
- 审核通过建议准确率

视觉风格：

- 深蓝 / 青绿商务风
- 大留白
- 卡片化布局
- 有过程流动画，但不过度炫技

## 7. 决赛演示脚本

10 分钟路演建议：

1. 痛点：高校审批和报名材料流程繁琐、容易漏项、规则分散
2. 方案：智审通是“会办事”的行政审批 Agent
3. 现场演示：
   - 导入比赛通知或学院制度
   - 提问“我能否单人参赛，截止时间是什么”
   - 上传报名材料截图
   - 系统 OCR 抽取字段并审核缺失项
   - 自动生成报名表单
   - 自动生成待办计划
4. 商业价值：学校、企业行政、产业园区都可复用
5. 技术亮点：RAG、工具调用、意图识别、多 Agent 编排、OCR、多模态
6. 未来落地：接入学校 OA、迎新系统、学工系统

## 8. 作品的关键加分项

优先级从高到低：

- 真正接入 OCR，不只做文本模拟
- 规则引擎配置化，不把规则写死在代码里
- 引用命中文档片段，保证答案可信
- 支持“问答 + 审核 + 填表 + 流程”的一体化
- 做一份真实的小型知识库
- 做一页商业价值看板
- 若时间够，再补一个国产小模型本地部署版本

## 9. 当前仓库建议

你现在这份仓库已经有：

- React 前端
- FastAPI 后端
- PostgreSQL
- Qdrant
- 基础问答 / 审核 / 填表 / 流程模块

但距离“第一名作品”还差几步：

- 目前更像 `Demo`
- 需要从单体功能页升级为 `产品化工作台`
- 需要接入真实 OCR
- 需要引入 `LangGraph` 做多 Agent 工作流
- 需要把规则结构化存到 PostgreSQL
- 需要补强商业化展示与路演故事

## 10. 最终建议的实施顺序

第一阶段：做稳闭环

- 打通文档上传、切块、向量入库、检索问答
- 打通 OCR -> 字段抽取 -> 规则审核 -> 表单预填
- 打通流程规划和记录留痕

第二阶段：做强产品感

- 重做首页与工作台 UI
- 增加证据引用和过程可视化
- 增加看板和量化收益展示

第三阶段：做冲奖亮点

- 接 LangGraph 多 Agent
- 接真实规则引擎
- 准备本地国产模型备选方案
- 准备路演 PPT、演示数据、故障降级预案

## 11. 一句话结论

最优解不是再换一个题目，而是把当前仓库升级成：

`一个能真实完成高校行政审批与比赛报名办理闭环的多 Agent 智能工作台`

这条路线最符合比赛要求、最容易展示商业价值，也最适合用你现有的 `PostgreSQL + Qdrant + Docker 服务器` 体系快速做出高完成度成品。
